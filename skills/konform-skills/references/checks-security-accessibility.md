# Security and accessibility checks

Technical checks that support the legal duties: **security of processing** (DPA 2017 s.31; GDPR Art. 32), cybercrime prevention (Cybersecurity and Cybercrime Act 2021) and **equal access** for persons with disabilities (see MU-A11Y-01 in `checks-mauritius-business.md`; EU-EAA-01, US-05 in `checks-international.md`). They are best practice everywhere and the evidence regulators look for after an incident.

Letters (A-N) refer to the inventory in `repo-scan-playbook.md`. Headers can be set in the app, the framework config (e.g. `headers()` in `next.config.js`) or the hosting config: if the repo contains the hosting config (`vercel.json`, `netlify.toml`, `_headers`, `nginx.conf`, `.htaccess`, `web.config`...) and the header is missing everywhere, report **FAIL**; if the hosting config is not in the repo, report **MANUAL** ("not set in the repo; confirm on the live site") even when the framework config sets no headers. The same applies to TLS settings. Report a root cause once: incident readiness overlaps MU-DPA-17 (procedure) and SEC-16 (logging).

## Security (SEC)

DPA 2017 s.31(2)(a) lists the measures expected: pseudonymisation and encryption; ongoing confidentiality, integrity, availability and resilience; timely restoration after an incident; and regular testing of the measures. Processors must be bound by a written contract (s.31(4)). The OWASP Top 10:2025 categories are given for each check.

| ID | Check | Look for (inventory H unless stated) | Fail if | Severity | Fix |
|---|---|---|---|---|---|
| SEC-01 | HTTPS everywhere | Redirect config (`force_ssl`, `SECURE_SSL_REDIRECT`, `UseHttpsRedirection`, host redirects), `http://` URLs in forms, scripts, iframes, API base URLs | Pages, forms or APIs reachable over plain HTTP; `http://` resources on HTTPS pages (mixed content) | Critical if personal data travels over HTTP; High otherwise | Redirect all HTTP to HTTPS (301), fix hard-coded `http://` URLs, add `upgrade-insecure-requests` to the CSP |
| SEC-02 | TLS configuration | `ssl_protocols`, load-balancer or CDN TLS policy, certificate automation | TLS 1.0/1.1 enabled; no automated renewal | High | TLS 1.2+ only (RFC 8996), automate certificates (e.g. Let's Encrypt). Usually MANUAL on managed hosting |
| SEC-03 | HSTS | `Strict-Transport-Security` in app or host config | Missing, or `max-age` under one year | Medium | `Strict-Transport-Security: max-age=63072000; includeSubDomains` (add `preload` once every subdomain is HTTPS) |
| SEC-04 | Content-Security-Policy | CSP in headers or `<meta http-equiv>`; `helmet`; framework CSP config | No CSP; `script-src` with `'unsafe-inline'` and no nonce/hash; `*` sources; no `frame-ancestors` and no `X-Frame-Options` | Medium | Start with `Content-Security-Policy-Report-Only`, then enforce; restrict scripts to known origins (also limits card-skimming) |
| SEC-05 | Other security headers | Header config | Missing `X-Content-Type-Options: nosniff`; missing or unsafe `Referrer-Policy` (`unsafe-url`, `no-referrer-when-downgrade` leak full URLs, including e-mails or order IDs in query strings, to third parties); no `Permissions-Policy`; `X-Powered-By`/version banners exposed | Low (Medium for unsafe Referrer-Policy) | `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, remove version banners. `X-XSS-Protection` is obsolete: set `0` or omit |
| SEC-06 | Session and auth cookies | Inventory E | Session/auth cookies without `Secure`, `HttpOnly` or `SameSite`; tokens in `localStorage` | Medium (High for auth tokens readable by scripts on sites with third-party scripts) | `Secure; HttpOnly; SameSite=Lax` (or `Strict`), `__Host-` prefix, short lifetimes, rotate on login |
| SEC-07 | Authentication and passwords (A07) | Password hashing, login throttling, MFA for admin, password reset flow | MD5/SHA-1/unsalted SHA-256 or reversible encryption for passwords; no rate limiting; admin without MFA | High (Critical for plaintext passwords) | bcrypt, scrypt or Argon2id via the framework's built-in hasher; throttle logins; MFA for admin accounts |
| SEC-08 | Secrets management | Secret patterns, committed `.env` files, `.gitignore` | Live keys, passwords or private keys committed | Critical | Remove from code and history, **rotate the secret**, use environment variables or a secret manager |
| SEC-09 | Personal data in logs, URLs and errors | Logging calls with personal fields; GET forms with personal data; analytics page URLs containing e-mails | Personal data or tokens written to logs or sent in URLs/query strings | Medium | Log identifiers, not content; POST forms; scrub PII before analytics/monitoring (e.g. Sentry `sendDefaultPii: false`) |
| SEC-10 | Access control (A01) | Endpoints returning user data, admin routes, object IDs in URLs, file download routes | User data reachable without authorisation checks (IDOR); unprotected admin or debug routes | Critical | Enforce ownership checks server-side on every request; deny by default |
| SEC-11 | Injection and input handling (A05) | Raw SQL with string concatenation, `dangerouslySetInnerHTML`, `v-html`, `{!! !!}`, the Jinja/Django `safe` filter, unvalidated uploads | User input reaches queries, HTML or the file system unsanitised | High | Parameterised queries, framework escaping, validate type/size of uploads and store them outside the web root |
| SEC-12 | Supply chain (A03, A08) | Manifests and lockfiles, outdated libraries (e.g. jQuery < 3.5, AngularJS 1.x, Bootstrap < 3.4.1/4.3.1), CDN scripts without `integrity` | Known-vulnerable or end-of-life packages; no lockfile; CDN scripts without Subresource Integrity | Medium (High for known-exploited vulnerabilities) | Update dependencies, enable automated updates and audits, add SRI or self-host |
| SEC-13 | Payment card data (PCI DSS v4.0.1) | Inventory L | Card fields in your own pages or API; any CVV storage; payment page loading unmanaged third-party scripts | Critical for stored card data or CVV; High otherwise | Use the provider's hosted page or iframe fields; never store CVV; on payment pages keep an inventory and integrity control for every script (req. 6.4.3) and detect tampering (req. 11.6.1), or confirm SAQ A eligibility (since Jan 2025 SAQ A merchants must confirm the site is not susceptible to script attacks) |
| SEC-14 | Encryption and resilience | DB/storage encryption settings, TLS to the database, field-level encryption for sensitive data, backup config | Special-category or identity data stored unencrypted; no backups or restore procedure | Medium (High for special categories) | Encrypt at rest and in transit, pseudonymise where possible, test backups and restores (DPA s.31(2)(a)(i)-(iv)) |
| SEC-15 | Vulnerability disclosure | `/.well-known/security.txt` (in `public/`, `static/`), `SECURITY.md` | No way for researchers to report a flaw | Low | Publish `security.txt` with `Contact:` and `Expires:` (RFC 9116); see `assets/security.txt` |
| SEC-16 | Logging, alerting and incident readiness (A09) | Security event logging, alerting, incident runbook | No security logs or no incident procedure | Medium | Log authentication and admin events, alert on anomalies, keep an incident plan that meets the **72-hour** breach notice (DPA s.25); see `assets/breach-response-plan.md` |
| SEC-17 | Error handling and misconfiguration (A02, A10) | `DEBUG = True`, `APP_DEBUG=true`, stack traces in responses, default credentials, directory listing, exposed `.git`/`.env` | Debug mode or detailed errors in production; exposed config files | High | Production configs with debug off, generic error pages, block dotfiles |

## Accessibility (A11Y)

Audit against **WCAG 2.2 AA** (W3C Recommendation, now ISO/IEC 40500:2025) and report **WCAG 2.1 AA** as the current legal floor where a law cites it (EN 301 549 v3.2.1 for the European Accessibility Act). Code review finds many issues, but contrast, keyboard flow and screen-reader output need a manual or browser test: say so.

| ID | Check (WCAG) | Look for (inventory M) | Fail if | Severity | Fix |
|---|---|---|---|---|---|
| A11Y-01 | Page language (3.1.1) | `<html lang>` in layouts; language switch for French pages (3.1.2) | Missing or wrong `lang` | Medium | `lang="en"`, `lang="fr"`; Kreol Morisien is `mfe` |
| A11Y-02 | Text alternatives (1.1.1) | `<img>`, `next/image`, background images with meaning, icon fonts, SVG icons | Informative images without `alt`; decorative images not hidden (`alt=""`) | Medium | Meaningful `alt` text; `alt=""` for decoration |
| A11Y-03 | Labels, instructions and errors (1.3.1, 3.3.1, 3.3.2, 4.1.2) | Form components | Inputs without an associated `<label>`, `aria-label` or `aria-labelledby` (placeholders are not labels); errors not tied to fields | High on checkout, sign-up and contact forms; Medium elsewhere | Visible `<label for>`, `aria-describedby` for hints and errors, announce errors |
| A11Y-04 | Zoom and reflow (1.4.4, 1.4.10) | Viewport meta tag, fixed-width layouts | `user-scalable=no` or `maximum-scale=1`; content breaks at 320 px width | Medium | Remove zoom restrictions; responsive layout |
| A11Y-05 | Keyboard and focus (2.1.1, 2.1.2, 2.4.3, 2.4.7, 2.4.11) | Click handlers on non-interactive elements, `tabindex` > 0, `outline: none` without replacement, modals and menus | Mouse-only controls; keyboard traps; invisible or obscured focus | High | Native `<button>`/`<a>`, visible `:focus-visible` styles, manage focus in dialogs |
| A11Y-06 | Names for links, buttons and frames (2.4.4, 4.1.2) | Icon-only buttons and links, `<iframe>` without `title` | Controls announced as "button" or "link" with no name | Medium | `aria-label` or visually hidden text; `title` on iframes |
| A11Y-07 | Titles, headings and skip link (2.4.1, 2.4.2, 1.3.1) | `<title>`/metadata per page, heading levels, skip link | Missing page titles, no `<h1>` or skipped levels, no way to bypass navigation | Low to Medium | Unique titles, logical headings, "Skip to content" link |
| A11Y-08 | Colour contrast (1.4.3, 1.4.11) | Design tokens, Tailwind/CSS colour pairs | Text below 4.5:1 (3:1 for large text and UI components) | Medium | Adjust tokens; verify with a contrast checker (MANUAL if only tokens are visible) |
| A11Y-09 | Media and motion (1.2.2, 1.2.5, 1.4.2, 2.2.2) | `<video>`, autoplay, carousels, animations | No captions; autoplay audio; auto-advancing content without pause; ignores `prefers-reduced-motion` | Medium | Captions/transcripts, pause controls, respect reduced-motion |
| A11Y-10 | No reliance on overlays | Overlay scripts (`third-party-services.md`) | An overlay widget is presented as the accessibility solution | Low (High if marketed as "compliant") | Fix the underlying markup; overlays do not make a site conformant |
| A11Y-11 | Accessibility statement and feedback | Route or page named accessibility/accessibilite | No statement or contact for accessibility problems | Low (High for EAA-scope shops) | Publish a statement (see `assets/accessibility-statement-template.md`) |
| A11Y-12 | WCAG 2.2 additions (2.4.11, 2.5.7, 2.5.8, 3.2.6, 3.3.7, 3.3.8) | Drag-and-drop UIs, small icon buttons, help links, multi-step forms, login | Targets smaller than 24x24 CSS px; drag-only interactions; users must re-enter data; login needs a cognitive test (puzzle CAPTCHA without alternative, no paste in password fields) | Medium | Bigger targets, click alternatives to dragging, prefill known data, allow paste and password managers |
| A11Y-13 | Accessible consent banner | CMP or custom banner component | Banner not reachable or operable by keyboard/screen reader; focus not moved to it; "Reject" hidden from assistive tech | High (it blocks both consent law and access) | Use a CMP with an accessible dialog, or fix the component (role="dialog", labelled buttons, focus management) |
